完成日期：2026-10-05。主结果采用修复引用格式解析器后、单独冻结的 `citation-adapter-v2 / run2`。本次完成更难的评估及相同问题的简单检索对照；报告 PDF 和演示仍按要求暂缓。

**现有系统在连续对话中更强，但本轮不能证明它总体优于简单基线。** Root AI 逐条审查后，现有系统完成 41/60 个回合，BM25＋同配置生成模型完成 44/60。现有系统连续对话为 18/20，基线为 8/20；基线对明确 ID、自然事实问法及年份范围更稳健。失败案例构成下一步改进依据，不能用原来较简单样本的 28/30 代替这次结果。

## 1. 问题、数据与公平性

研究问题：结构化电影路由、筛选与对话控制，在真实用户表达下有哪些可观察的收益与代价？与一个简单、可复现的检索生成实现相比，它能否完成相同任务？

两端使用同一份 4,659 部电影的 release 元数据。60 个作者选定的回合包括同名电影与明确 ID 各 5 题、5 组繁简体变体共 10 题、10 题多条件推荐、10 题领域/证据边界，以及 10 段两回合对话。第一回合也计分，第二回合检查条件替换、指代、自己的第二张电影卡、去重和领域切换。题目不是随机总体样本；部分第一回合重复，亦有与原 30 题相似的任务。

事实 gold 来自固定元数据字段。推荐允许任意满足全部条件的三部独立电影，不要求匹配某个固定排序；每题的全库可行性在模型执行前检查。导演共同署名与元数据中明确的“即”别名允许匹配。多轮的动态 gold 按该端实际历史确定，绝不把现有系统的电影卡复制给基线。例如 M06.2 中，两端的“第二部”分别是《醉拳》和《警察故事續集》，两端答案均通过。

| 实现 | 设置 |
| --- | --- |
| 现有系统 | 固定公开 API/release；原生结构化路由、筛选、向量检索、证据控制及对话处理；可走确定性事实/回退路径 |
| 简单基线 | 本地 CPU BM25，`k1=1.5, b=0.75, top_k=8`；对 JSON 元数据各字段统一计分；通用 OpenCC 繁简归一、汉字单字/双字及英文数字词元 |
| 基线对话检索 | 当前问题＋最近最多四回合的问题和实际电影 ID；生成器另外收到该端完整有界历史。没有专用人物/类型/年份路由，也不接收 gold 或候选正确答案 |
| 生成 | 同一配置模型 `gemini-3.5-flash-lite`；基线 Vertex/global，1,024 输出 token、默认 temperature、一次 SDK attempt、证据限定提示词 |

该比较评估**整个实现**。两端的提示词、证据选取、确定性处理、内部重试和运行环境并不完全相同，因此不是“仅替换检索器”的因果消融，也不能把差异全归因于 BM25、向量检索或某一个路由模块。生产服务仍有五份 PDF 的 21 个片段；这些资料未提供给基线。本次全部返回引用均为元数据；证据不足题使用没有这五份深度文档的电影。没有改生产代码、release 或资源配置，没有新增云资源。

题目、catalog、运行源、提示词、模型及 release/policy 身份在执行前冻结，结束只读复查。每个回合交替两端先后次序，各端使用自己的真实历史；不对单个失败请求重试。三次连续调用失败的停止保护未触发。

## 2. 实际运行与评估协议修复

正式修复版于 **2026-10-05 18:40:00–18:43:23 HKT** 执行，两个端各尝试 60 次，均得到 59 个完整回答。保留现有系统 B08 的 `RemoteDisconnected` 和基线 M09.1 的 `ClientError`；后者耗时 51.13 秒。没有保存含凭据的错误体，不能推断 ClientError 的具体服务端原因或声称账号鉴权失败。M09.2 因上一回合失败而没有实际历史，属于依赖失败；不删除它或从分母中去掉它。

本次协议有两个诚实保留的修复记录：

1. 首次启动在写冻结清单前查错 OpenCC 发行包名称，退出，正式题目调用为 0；实际锁定环境为 OpenCC 1.4.1。修复包名查询并加入回归检查。
2. `run1` 已完成 120 次逻辑调用，但基线解析器把 `citation_ids` 中的裸电影 ID 拒绝，即使正文有正确的 `[metadata:ID]` 且对应记录已检索。这还丢掉了后续对话应有的历史。原始机械总分为 43/60 与 29/60，**不能用于证明现有方法更优**。完整原记录、冻结清单、失败及源字节保留，未改分、未与主结果合并。

修复只对已在 supplied evidence 中的裸 ID 加标准前缀，不改答案，不接受未知 ID、缺失正文标记或重复身份。独立 AI 审查确认题目、case builder、BM25、提示词、模型、评分和历史规则未改变。随后另行冻结并执行 run2，绑定真实父记录哈希。因为相同题目已在诊断中见过，run2 是明确披露修复后的实现对照，**不宣称全新盲测或独立 holdout**。本次共两个版本各 120 次逻辑调用及一次独立基线连通测试；未对算法或题目做答案驱动的调优。

## 3. 评分与逐条审查

自动检查目标字段、电影身份、引用结构、推荐数量/去重/全部筛选，以及真实历史。正文引用 ID 中的年份不能代替回答。拒答后给出无依据内容、否定 gold 的事实、带正确电影卡却拒绝推荐，均不能通过。仅附带泛化“请确认”的单版本答案不能算消歧。

Root AI 实际阅读全部 120 个输出或错误，检查对应字段、电影卡、检索资格和各端历史。它不是人类审计。主表使用这份明确逐条 AI 判定，原始自动分数与输出保持不变。

| 自动→AI 审查修正 | 处理 |
| --- | --- |
| 基线 A1a、A2a、A3a、A5a | 正确列出两个版本并请提供所指年份/ID；自动短语表漏识别。由错误改为合理澄清 |
| 基线 B06、B07 | 明确说没有票房/评分记录，没有编造数值；由错误改为合理拒答 |
| 现有系统 B09 | 没有编造镜头分析，但错误地把问题解释为“同时指定电影与人物片单”；安全拒绝不等于合理解释。由通过改为任务错误 |

因此原始自动分为 **42/60 vs 38/60**，审查后为 **41/60 vs 44/60**。这七处判定改变逐条留痕，不能在报告中只挑对某端有利的口径。

## 4. 定量结果

| 挑战组 | 回合数 | 现有系统 | BM25＋LLM |
| --- | ---: | ---: | ---: |
| 同名消歧及明确 ID | 10 | 5/10 | 10/10 |
| 繁简体事实变体 | 10 | 8/10 | 10/10 |
| 多条件推荐 | 10 | 2/10 | 6/10 |
| 领域/证据边界 | 10 | 8/10 | 10/10 |
| 连续对话 | 20 | 18/20 | 8/20 |
| **总计** | **60** | **41/60（68.3%）** | **44/60（73.3%）** |

| 审查类别 | 现有系统 | 基线 |
| --- | ---: | ---: |
| 正确完成事实/推荐任务 | 27 | 28 |
| 合理澄清 | 5 | 5 |
| 合理拒答 | 9 | 11 |
| 任务未完成或语义/筛选错误 | 18 | 15 |
| 请求失败 | 1 | 1 |

“任务错误”包含安全但未完成的部分回答，不等于每次都产生幻觉。例如基线只检索到两部合格电影时坦白返回两部，仍不能满足全库可行的三部请求。M09.2 也不归因于独立的记忆推理错误：实际历史在前一请求失败后为空。

配对表为双方通过 30、仅现有系统通过 11、仅基线通过 14、双方失败 5。现有系统减基线的成功率差为 **−5.0 个百分点**。预定按 40 个对话/变体/主题 cluster 抽样的 10,000 次 bootstrap 描述区间为 **[−24.6, +15.0] 个百分点**（固定种子 4136）。这不是随机总体采样；重复问题可能还有跨 cluster 相关性。区间只用于本小样本的敏感性描述，不能证明总体优劣或相等。

全部 60 次尝试的观测耗时中位数为 **0.733 秒 vs 1.367 秒**，最大值 **3.741 秒 vs 51.125 秒**，包括失败请求。串行混合任务、不同本地/云路径及确定性回答使其不能代表模型速度、吞吐量或稳定 SLO。

基线 59 个成功 provider 回执记录输入 **107,411**、输出 **9,113**、总计 **116,524** token；失败请求的潜在用量不在这个数中。生产 API 未暴露 provider 用量，故不比较 token 或费用，也不把每个系统回答都称为一次 LLM 推理。

现有系统有 39 个含引用的回答、69 条引用；基线有 50 个、95 条引用，全部为 `movie_metadata`。返回卡片的电影名、导演、演员、类型、日期、tier 共 912 个字段比较与冻结 catalog 一致。引用身份合法不保证推荐满足条件或解释正确，不能因此宣布“100%无幻觉”。

## 5. 输出与中间过程案例

**可观察的对话收益：** M02.2“改成1990年代，其他条件不变”中，现有系统保留吴宇森/动作条件，返回《喋血街頭》《辣手神探》《縱橫四海》三部，日期与导演均合格。简单基线 top eight 中只包含一部合格记录，因此只能返回一部。M01.2 与 M03.2 也体现了类似的检索覆盖差异。这个证据支持当前实现对所测对话任务有收益，但未隔离是哪一模块造成。

**明确 ID 仍被过度拒答：** A1b 已指定 `1986_YXBS_001`，现有系统却回复“现有字段不足”；该记录的导演是吴宇森。基线正确回答并引用目标。五个明确 ID 回合都出现同类问题。离线原生源码复现显示 `_canonical_metadata_intents` 对普通标题问导演返回 `director`，加入自然的“電影 ID …”前缀后返回 `None`；L1 的“請查詢 … 上映年份”也返回 `None`。这与线上行为一致，但离线函数不是生产请求内部 trace。

**年份范围被收窄：** C01 请求 1980–1999 年吴宇森动作片，全库有 11 部合格电影。现有回答显式显示 **1980–1980 年**并称不足三部。原生 `_year_constraints` 的离线复现也把中文“1980至1999”解析为 `(1980,1980)`。基线从四个合格检索记录中返回三个。C05/C07/C10 有相同年份表达风险，不能将这些失败归咎于缺少电影数据。

**多条件 AND 漏掉：** C03 要求动作**和**喜剧。现有系统把《武館》列入推荐，但 catalog 类型为“动作、剧情”，不含喜剧。正文没有伪造它的喜剧标签，仍然违反用户的交集条件。基线在本题只检索到两部合格电影，诚实返回两部；两个端都未完成任务，原因不同。

**基线也会忽视已经检索到的证据：** C08 top eight 中有六部满足周星驰单独/共同导演、喜剧、年份条件的电影，却只返回两部并称仅有两部。这是 reader 对共同署名/别名证据的使用问题，不能都解释成 BM25 召回不足。M02.1 也在四部合格检索记录中只使用两部。

**过度消歧与失败传播：** M05 中，基线把《無間道II》《無間道III終極無間》当成《無間道》的同名版本；这些是不同完整片名。它列出正确导演，却为明确片名要求再次消歧，下一回合延续了这个错误。另一个 M09 会话的先前请求真实失败，第二回合缺少上下文，不能把这种依赖失败解释成同一类 reader 错误。

**当前系统仍有自然续问缺口：** M04.2“现在换成杜琪峯导演的”不能解析该已存在导演；M07.2“不要与刚才重复”被错误解释成多位正向人物。虽然对话组总体较好，不能宣称所有续问都已支持。

## 6. 限制与交付范围

这是作者选择的 metadata 诊断集、单次修复版运行与 AI 审查，不是独立人类标注、随机泛化估计、稳定性测试或受控因果消融。只验证 release 中存储的字段；没有独立核验电影资料本身是否完整/绝对正确，也没有测试 PDF 深度 RAG、海报界面和并发。十段两回合对话不覆盖更长历史或恶意输入。

下一轮工程优先级可由具体失败确定：明确 ID/自然事实用语的残留词处理、中文年份区间、类型交集及人物切换/去重表达；基线则需改进条件检索覆盖和共同导演证据使用。**本次没有改这些生产行为，也没有为了提高分数重跑它们。**

原 `study-01` 的原始 28/30 与响应哈希均保留；新结果独立记录。组号、成员姓名/学号仍暂缺，`human_audits: pending`、`submission_ready: false`。这里完成的是两项技术评估交付，不是课程平台提交或满分保证。
